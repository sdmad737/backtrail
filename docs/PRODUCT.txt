TRAVIS — CURRENT PRODUCT, OCTOBER 24, 2026

AUTHORITY
The latest user request and TRAVIS-BUILD-BRIEF.txt supersede earlier optional-AR,
visual-only dead-reckoning and GPS-only briefs. Preserve the chosen Android starter.
Previous bootstrap decisions remain under history/ for provenance, not current scope.

PROMISE AND CORE LOOP
Know where you are, record where you have been, remember meaningful places and
help retrace the actual ordered route with no cloud runtime dependency.
Start outing -> record -> save photo + optional note/reminder -> ask/select a
saved memory -> Find in AR -> recognize the original landmark -> resume retrace
or explicitly mark the requested pickup collected -> return to recorded start.

CORE SURFACES
Map: prepared offline surroundings, measured position/uncertainty, segmented
recorded route and photo markers. Missing map coverage leaves the trace visible.
AR: live rear camera, sensor-driven approximate direction and straight-line
measured distance to the selected saved location or next recorded waypoint.
Show the original photo where available. Suppress cues for stale/weak fixes or
unreliable heading. No photo is silently borrowed from another checkpoint.
One compact, scrollable bottom sheet carries state and primary actions. Find
and Retrace are distinct modes sharing one source of truth across Map/AR.
Selecting a memory never advances or replaces the saved retrace cursor.

GEMMA'S ROLE
Gemma 4 E2B + LiteRT-LM 0.18.0 describe a saved real image and resolve a free-text
query against up to 12 recent saved descriptions/notes. The model returns strict
bounded JSON with allowed IDs. User reviews the source photo and chooses Find.
No fabricated coordinates, model-driven progress or automatic claim of recognition.
Invalid/late/unavailable results remain visible. Original photos and GPS survive
model failures. No distillation, fine-tuning or extra embedding model selected.
Two-image comparison and richer assistant APIs exist on the inference service but
are not wired to normal product screens yet. The live app now prefers the pinned
G6/NPU artifact when present, otherwise the pinned generic/GPU artifact.

DETERMINISTIC RESPONSIBILITIES
GPS service, segment boundaries, true bearing geometry, quality gates, ordered
reverse traversal, persistence, reminders and explicit confirmation/undo belong
to ordinary code. Retrace stops at recording gaps; it invents no connecting route.
Arrival in Find does not mark a pickup collected. Collection is a separate action.
Return reminders require opt-in, departure, then repeated good arrival fixes.
A requested time reminder uses an inexact local Android alarm.

PLATFORMS AND DEMO
One native Android app is the technical foundation. Portable Explore is an
interactive browser product showcase for iPhone and Android screen sizes. It has
replay coordinates/heading, NPS photo previews and explicitly sample model answers.
It is isolated from saved live outings. Native iOS remains future work.
The native app also has an opt-in Explore mode. Normal startup is live mode and
never silently substitutes fixtures for missing models or sensors.

SCOPE LIMITS
Approximate camera guidance is core; richer world-tracked AR remains a hardware
exploration gate. No ground-anchored arrows, GPS-free localization, autonomous
route planning, shortcuts, route safety certification, rescue transmission,
cloud fallback, survival chatbot, plant-safety verdicts, voice input/output,
continuous pocket camera, telemetry or download-at-use assets in the demo.
A physical Pixel trial is the next gate, not a property proven by compilation.
