How it works

Two Gemma models do the understanding. Plain code owns everything that must be exact.

Sensors

Camera photo or live frame
Microphone (16 kHz WAV)
GPS trail, compass, step count

Gemma on the NPU

Gemma 4 E2B (vision + audio): describe a landmark, compare two photos, answer questions, parse a spoken note

EmbeddingGemma 2 (text + image + audio, 256-d): rank saved spots by meaning in 13 to 30 ms

LiteRT-LM 0.18.0 · Google Tensor runtime 2.3.0 · Tensor G6 NPU

Guard rails in code

JSON-schema-forced decoding
Strict validators (ids must exist)
Safety guard: no “safe to eat” verdicts
Request gate: stale answers dropped

The walker decides

Every AI result is a proposal shown next to your own photo. Confirm or Undo. Route progress, distances and reminders are deterministic code, never model output.

“Am I going the right way?” is answered by code from GPS, compass and trail geometry. Gemma’s photo check is supporting evidence only: a match can support a yes, and a mismatch downgrades it to “not sure.” The camera alone can never say yes.

One sentence per box. The architecture point judges care about: we separated what needs understanding (Gemma) from what needs to be exact (code), and we put a schema, a validator and a human tap between the model and the route. The cheap model (embeddings, 13 ms) narrows; the big model (Gemma, seconds) only runs when the walker asks.
