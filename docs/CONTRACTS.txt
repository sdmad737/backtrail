TRAVIS — IMPLEMENTED CONTRACTS

CANONICAL TYPES
contracts/TravisModels.kt: TrailPoint, Outing, Memory, OutingPhase, PickupPhase,
GuidanceMode, TravisSurface, TravisUiState and TravisAction for the live product.
contracts/Models.kt + Ports.kt: existing inference RequestContext, ImageRef,
Checkpoint, typed proposals, InferenceState and VisionService. Existing bootstrap
ports are retained for compatibility; they do not imply separate implementations.

DATA / OWNERSHIP
OutingStore owns app-private atomic JSON + original JPEG paths. Outing contains
ordered GPS points with segment IDs, memories and an independent retraceIndex.
A process restart preserves data but pauses a previously recording outing.
A failed/corrupt metadata load preserves its file and refuses silent overwrite.
TrailPoint carries position, accuracy, wall time and segment; the location service
also checks Android monotonic sample age/order before admission. Callbacks and
atomic writes are serialized; invalid coordinates/accuracy are rejected. Provider
interruptions and >15-second callback gaps start disconnected segments. Stationary
GPS callbacks keep guidance fresh; recorded density remains 2m or 10 seconds.
A provider-generation check prevents a pre-outage fix reappearing after recovery. A missing/poor fix
saves a photo with unknown location; no cached or invented coordinate is attached.
Memory stores original photo, exact note, optional saved fix/route index,
Gemma description/provenance and opt-in pickup state. Files never go in UI bitmaps.
titleEdited protects user titles from subsequent model description changes.
Capture creates an unsaved original first; Retake/Cancel discard that draft.
Save commits its capture-time position and exact optional note before local Gemma
description. Pending atomic saves retain originals if their ViewModel is cleared.

ADAPTERS
TravisViewModel: action composition, immutable screen state, request gate, session
and selected memory/mode. UI renders state and sends actions, not route decisions.
RecordingService: user-started foreground GPS; remains independent of inference.
LiveSensors: observed GPS/heading/reliability/failure/tracking status flows.
NativeCamera: CameraX preview + captured original app-owned JPEG; visible errors.
CameraHeading: one listener supplies rear-camera -Z projection and a separate
map display-top compass, remapped for all four screen rotations; geomagnetic declination
for true north; unstable/near-vertical projection fails closed. Physical calibration
and portrait/landscape behavior require Pixel measurements.
OfflineTrailMap: bundled hybrid/terrain/aerial XYZ rasters, geographic trace,
continuous pan/zoom and measured-position cone. Aerial1024px sources are mapped
to their zoom16 XYZ footprints with coarser tiles underneath. The decoded LRU
cache is bounded to24MiB. No network path.
LocalVisionService: one serialized local request with strict result validation,
using a cached engine. The live app selects G6/NPU when that pinned model is
present, otherwise generic/GPU. Model replacement serializes with service ownership; cancelled teardown completes off
the UI thread before a new engine can be created. New requests wait for replacement.
Description persistence checks revision and original image identity inside the store lock.
ExploreFixture and the separate browser ReplayAdapter are explicitly opt-in samples.

ASYNC INVARIANTS
RequestContext carries sessionId, unique requestId, outing ID, catalog revision and
checkpoint ID. RequestGate validates exact identity and consumes a result once.
Outing.revision is the memory-catalog revision, not a GPS tick counter. Saving a
memory increments it; GPS appends do not invalidate a legitimate photo request.
New session/selection/cancel invalidates pending inference. Results also check the
current committed outing and catalog revision. Invalid/stale output never changes
progress. Description persistence cannot remove the original photo/route.
Generation cancellation does not imply forcibly interruptible native engine init.

NAVIGATION
GuidanceMode NONE / RETRACE / FIND_LANDMARK and Map/AR surface are orthogonal.
Find selects only an existing saved ID and optional real saved point. It preserves
the home retraceIndex and suspends any active memory return separately. Memory
returns keep their own next/goal/start indices. Reaching a memory retains its
confirmed progress; explicit continuation starts from there toward home. Undo is
bound to outing/destination/goal/start and cannot mutate a cursor while finding.
Deleting a memory clears both active and suspended references to that destination.
Strict matched-route direction requires a fix no older than5s with <=15m reported accuracy; recorded
geometry must have <=25m accuracy. Heading rejects reported uncertainty over25°.
Unknown numeric heading uncertainty remains unknown; it never becomes precise.
RouteFollower matches a bounded local portion of the ordered polyline using three
distinct fixes. Its look-ahead respects sustained corners; short GPS wiggles are
not treated as turns. When strict matching is uncertain, a separately labelled
approximate pointer uses the map-quality current fix and the local route target.
Near-place uncertainty does not remove the pointer. Off-route/ambiguous references
are waypoint bearings; gap references stop at the contiguous segment boundary. GPS outage/reacquisition can retain the last measured
route bearing as explicitly historical display data, never as a current fix. Near a destination, overlapping GPS uncertainty requires the original photo.
Measured progress may advance intermediate points through a session/cursor/goal
checked atomic write. It never recognizes, collects or completes the destination.
Final confirmation is explicit. Segment gaps have no invented connector. Remaining
distance/progress are approximate measured position along the recorded route.
Direct Find is labelled separately and does not claim a traversable connection.
A retrace waypoint without a matching saved photo is labelled as a waypoint.

REMINDERS
Pickup NONE -> WAITING_TO_LEAVE -> ARMED -> NOTIFIED -> COLLECTED. Three consecutive
acceptable observations are needed at leave and return thresholds. Notification
transition is persisted before delivery, preventing repeated alerts on restart.
Find recognition does not imply collection. User explicitly marks collected.
Departure alerts operate only in Retrace, with distance/accuracy gating, repeated
observations, hysteresis and cooldown. Find resets departure evidence; resuming requires fresh evidence for the current
target. The monotonic cooldown survives a Find detour. Committed pickup notices
are delivered even if GPS is disabled during the storage write.
Time reminder is user requested, inexact, replaces the previous time reminder and
is not restored after reboot. Notification permission/channel state still governs
delivery. No guarantee of real-world timing is established by this implementation.

GPS-CONTINUITY UPDATE — OCTOBER 24, 2026
GuidanceContinuity retains presentation-only bearing/distance/age for the same
journey, mode, destination and route cursor during weak/missing GPS or recovery.
It never feeds the retained location into RouteFollower, storage, reminders or
confirmation. Distance/progress freeze; confirmation and approach haptics stay off.
No previous bearing means no invented bearing. Ambiguous/off-route/gap/near-place
uncertainty does not resurrect an old arrow. Changing the target clears the cache.
A separate lastKnownFix keeps a muted historical map marker. CameraHeading uses
a valid current/saved geographic region for declination; a fresh GPS fix is not
required for an otherwise reliable compass. Sensor lifetime depends on foreground
Map/Camera visibility, not GPS quality. Unreliable compass offers an explicitly
fixed north-up bearing reference rather than pretending to track phone rotation.

JOURNEY DELETION
DeleteOuting is user-confirmed. OutingStore.delete commits atomically before
removing only unreferenced app-owned photos. A session tombstone rejects queued
mutations of deleted IDs. Active deletion invalidates inference and stops GPS,
then rechecks current identity before clearing UI. Saving photos blocks deletion.
No model, map, unrelated journey or external file is deleted. Matching scheduled
reminders and per-place notifications are cancelled.
